# PLAN.md — The pi-myself Blueprint

This file is the canonical record of what we decided and why. If a later change contradicts it, update this file in the same commit. Status markers: ✅ decided · 🔜 planned · ⏸ deferred.

## 1. Goal

**pi-myself** = a pi coding-agent harness built AROUND mattpocock/skills as the process core.

- **Core (process)**: Matt Pocock's 25 promoted skills, consumed **verbatim** — never fork their text. Upgrades must stay cheap.
- **Harness (runtime)**: pi extensions, task-agent roles, slash prompts, tests — ported from `pikit-template/` (heyhuynhgiabuu/pikit) and rebuilt only where Matt's skills need pi-specific support.

Two prior repos live in this workspace for reference: `skills/` (vendored upstream clone, relocated to `vendor/mattpocock-skills/`) is now PART of pi-myself; `pikit-template/` is reference-only source material for the harness.

## 2. Decisions ✅

| # | Decision | Choice |
|---|---|---|
| D1 | Work tracking | **Matt's tracker wins.** Issue tracker via `/setup-matt-pocock-skills` config (`docs/agents/issue-tracker.md`, GitHub / GitLab / local `.scratch/<feature>/issues/`). The pikit `.pi/artifacts/{TODO,PLAN,PROGRESS,DECISIONS}.md` system is **dropped** as canonical work tracking. Keep `.pi/MEMORY.md` (memory layer, different job). |
| D2 | Upstream distribution | **Path A — vendored**: `vendor/mattpocock-skills/` is the upstream git clone living in this repo; `scripts/sync-skills.mjs` fast-forwards it, hashes all 25 promoted skills into `skills-lock.json`, regenerates prompt wrappers. Never edit `vendor/mattpocock-skills/**` (including prose patches); pi-side adaptations live in the harness layer only. |
| D3 | Subagents | **Use pi-task as-is** (`npm:@heyhuynhgiabuu/pi-task`); we own only `pi.skills` role overrides (`.pi/agents/`). Revisit native delegation only if pi ships one. |

### Consequences (binding)

- pikit skills that overlap Matt's are **dropped**, not merged alongside: `grilling`, `test-driven-development`, `improve-codebase-architecture`, `planning-and-task-breakdown`, `code-review-and-quality`, `debugging-and-error-recovery`, `documentation-and-adrs`, `cloudflare`.
- pikit prompts that own a process (`/create`, `/plan`, `/ship`, `/research`) are **dropped**; Matt's flow is the only process narrative (`/grill-with-docs` → `/to-spec` → `/to-tickets` → `/implement`, detours `/wayfinder`, `/triage`, `/diagnosing-bugs`; router = `ask-matt`). Harness prompts that remain: `/verify`, `/fix`, `/init`.
- One flow, one vocabulary. APPEND_SYSTEM.md routes to Matt's skill names only.

## 3. Three-tier state boundary ✅

| Tier | Owner | Contents |
|---|---|---|
| **Domain** | Matt's conventions | `CONTEXT.md` (shared language), `docs/adr/`, `docs/agents/{issue-tracker,domain,triage-labels}.md` (per-repo, generated by `/setup-matt-pocock-skills`) |
| **Work tracking** | Matt's issue tracker | specs, tickets, blocking edges, triage roles; local default `.scratch/<feature>/issues/` (gitignored is fine — disposable units) |
| **Harness** | pi-myself | `.pi/MEMORY.md` (durable distilled knowledge), `recall` over session JSONL history, safety audit, session helpers |

Rule: MEMORY.md is distilled knowledge, not a copy of CONTEXT.md vocabulary or of tracker state; if something belongs upstream, move it there.

## 5. Matt-skills → pi mapping (the gaps we close) ✅

| Gap in pi | Harness answer |
|---|---|
| No Skill tool; docs say models don't always `read` SKILL.md | **`skill-tool` extension**: registers a `skill` tool whose enum contains ONLY model-invoked skills → Matt's `Call the Skill tool with "grilling"` works verbatim; `invocation.md`'s invariant (user-invoked skills unreachable by the model) becomes harness-enforced, not prose-enforced. Unknown/user-invoked names return a message telling the human to run the wrapper. |
| User-invoked skills only reachable as `/skill:<name>` | **Generated prompt wrappers** at `.pi/prompts/<name>.md` (AUTO-GENERATED by sync-skills, never hand-edited) so the human types `/wayfinder`, `/to-spec`, `/setup-matt-pocock-skills` with argument hints. |
| No subagents | **pi-task** + our roles: `scout` is the research sub-agent, `reviewer` is the independent read-only review used by `implement`/`code-review` closing and by any completion claim. |
| Tracker ops are freeform prose per run | ✅ **`tracker` extension** (shipped Phase 2-3): one tool, two backends. Local markdown (`list/frontier/show/create-ticket/create-map/claim/resolve/tick/status/block/comment` over `.scratch/`) and GitHub Issues (`gh-*` ops via the `gh` CLI: issues carry `**Blocked by:** #N` / `Part of: #N` body lines, triage roles and wayfinder types are labels, claim = assign @me, resolve = close with a resolution comment). Pick the backend `docs/agents/issue-tracker.md` configures. GitLab keeps its tracker doc's own workflow for now. |
| PHASE-BOUNDARIES.md needs a ~150k smart-zone awareness | ✅ **`smart-zone` extension** (shipped): measures the last turn's usage against ~150k and notifies at 60%/85%/100% with the boundary-decision order from PHASE-BOUNDARIES.md (continue → /clear → /handoff → subagent → /compact). Advice only — never compacts on its own. `/smartzone` prints the current reading. |
| pi has no permission system | Port pikit's `safety` extension (block/confirm on `tool_call`, audit log, `/safety`). |
| Context loss after compaction | Port `dcp/recall` + `continue-after-compaction`; APPEND_SYSTEM tells agents to `recall` before guessing. |

## 6. What we kept / dropped from pikit

**Extensions**: keep `safety/`, `dcp/`, `continue-after-compaction`, `tps`, `shortcut-continue`; drop `todo.ts` (artifacts are gone per D1) and `herdr-agent-state.ts` (Herdr-specific).

**Skills** (keep in `.pi/skills/`): `memory`, `verification-before-completion`, `typescript-coding-standards`, `api-and-interface-design`, `deprecation-and-migration`, `security-and-hardening`, `source-driven-development`, `browser-tools`. Everything overlapping Matt: dropped (list in §2).

**Prompts**: keep `/verify`, `/fix`, `/init`; drop `/create` `/plan` `/ship` `/research` `/is`; add generated wrappers.

**Pirit tests**: rehomed into our hygiene gates (§7). **Themes**: ⏸ optional, later. **DESIGN.md, sprint templates, bin/cli.js**: dropped.

## 7. Test gates 🔜

- **Upstream parity**: 25 promoted dirs ≡ `plugin.json`; dir name ≡ frontmatter name; pi name regex `[a-z0-9-]+`; description ≤ 1024 (pi limit).
- **invocation.md as tests**: every user-invoked skill has `disable-model-invocation: true`; every `Call the Skill tool with "x"` target exists AND is model-invoked; skill-tool enum = exactly the model-invoked set.
- **Lock integrity**: `skills-lock.json` hashes match working tree; `sync-skills.mjs --check` in CI.
- **Our `.pi/skills`**: description prefix/length/no-first-person (pikit's gates, ours only — never asserted against upstream).
- **Assets**: relative references inside every SKILL.md resolve (both trees).
- **Prompts**: hand-written ones discover gates from repo guidance (no assumed npm scripts, NOT DECLARED ≠ PASS, evidence contracts); wrappers fresh vs vendored set.
- **Markers**: no `FIXME:` in tracked code.
- Extension unit tests (ported + new for skill-tool).
