# PLAN.md — The pi-myself Blueprint

This file is the canonical record of what we decided and why. If a later change contradicts it, update this file in the same commit. Status markers: ✅ decided · 🔜 planned · ⏸ deferred.

## 1. Goal

**pi-myself** = a pi coding-agent harness built AROUND mattpocock/skills as the process core.

- **Core (process)**: Matt Pocock's 25 promoted skills, consumed **verbatim** — never fork their text. Upgrades must stay cheap.
- **Harness (runtime)**: pi extensions, task-agent roles, slash prompts, tests — ported from `pikit-template/` (heyhuynhgiabuu/pikit) and rebuilt only where Matt's skills need pi-specific support.

Two prior repos fed this one: `skills/` (vendored upstream clone, relocated to `vendor/mattpocock-skills/`) is now PART of pi-myself; `pikit-template/` (heyhuynhgiabuu/pikit at `0003cb8`) was the reference checkout for the harness ports and was deleted from the workspace on 2026-09-15 after a final pass found nothing left to port (see §8).

### Consequences (binding)

- pikit skills that overlap Matt's are **dropped**, not merged alongside: `grilling`, `test-driven-development`, `improve-codebase-architecture`, `planning-and-task-breakdown`, `code-review-and-quality`, `debugging-and-error-recovery`, `documentation-and-adrs`, `cloudflare`.
- pikit prompts that own a process (`/create`, `/plan`, `/ship`, `/research`, and since 2026-09-14 `/fix`) are **dropped**; Matt's flow is the only process narrative (`/grill-with-docs` → `/to-spec` → `/to-tickets` → `/implement`, detours `/wayfinder`, `/triage`, `/diagnosing-bugs`; router = `ask-matt`). Harness prompts that remain: `/verify`, `/init`, `/remember`, `/setup-pi-myself`.
- One flow, one vocabulary. APPEND_SYSTEM.md routes to Matt's skill names only.

## 3. Three-tier state boundary ✅

| Tier | Owner | Contents |
|---|---|---|
| **Domain** | Matt's conventions | `CONTEXT.md` (shared language), `docs/adr/`, `docs/agents/{issue-tracker,domain,triage-labels}.md` (per-repo, generated by `/skill:setup-matt-pocock-skills`) |
| **Work tracking** | Matt's issue tracker | specs, tickets, blocking edges, triage roles; local default `.scratch/<feature>/issues/` (gitignored is fine — disposable units) |
| **Harness** | pi-myself | `pi-workspace-memory` records (durable distilled knowledge; `state` facts + `event` findings, outside git), `recall` over session JSONL history, session helpers |

Rule: memory is distilled knowledge, not a copy of CONTEXT.md vocabulary, tracker state, or a research report; if something belongs upstream, move it there and let memory point at it.

## 5. Matt-skills → pi mapping (the gaps we close) ✅

| Gap in pi | Harness answer |
|---|---|

Unknown/user-invoked names return a message telling the human to run the wrapper. |
| User-invoked skills only reachable as `/skill:<name>` | pi's native `/skill:<name>` slash commands (`enableSkillCommands: true`; args append via `_expandSkillCommand`). The generated prompt-wrapper layer (~14 files + sync logic) was **removed 2026-08-30** as redundant — one palette entry per skill. `setup-project.mjs` sets the key in consuming repos. |
| Skills reference a memory the model can search | ✅ **pi-workspace-memory** (D4): `memory_search`/`memory_read`/`memory_write` tools, first-turn injection of the newest records, a next-turn notice when another session changes them; the harness `memory` skill teaches search → knowledge view → structured write, and the post-compaction prompt consults it after `recall`. |
| No subagents | **pi-task** + our roles: `scout` is the research sub-agent, `reviewer` is the independent read-only review used by `implement`/`code-review` closing and by any completion claim. |
| Tracker ops are freeform prose per run | ✅ **`tracker` extension**: one tool, two backends, covering every field-level operation the skills perform (2026-09-15 audit). Local markdown over `.scratch/`: `list/frontier/show/create-spec/create-ticket/create-map/claim/resolve/out-of-scope/tick/status/block/comment`. GitHub Issues via the `gh` CLI: the same plus `gh-triage`; native sub-issue + dependency edges mirrored by `Part of: #N` / `**Blocked by:** #N` lines, triage roles mapped through `triage-labels.md`, wayfinder types as `wayfinder:<type>` labels, claim = assign @me, resolve = answer comment + close + gist into the map. Pick the backend `docs/agents/issue-tracker.md` configures. GitLab keeps its tracker doc's own workflow. |
| PHASE-BOUNDARIES.md needs a ~150k smart-zone awareness | ✅ **`smart-zone` extension**: measures the last turn's usage against ~150k; since 2026-09-14 the reading lives in the footer status past 60% and the boundary-decision order from PHASE-BOUNDARIES.md (continue → /clear → /handoff → subagent → /compact) toasts once when the level crosses 85%/100% (pi's own footer already shows raw context %, so the meter only adds the zone and the advice). Advice only — never compacts on its own. `/smartzone` prints the current reading. Thresholds, usage summation, and the env override (`PI_SMART_ZONE_LIMIT`, min 1k, garbage falls back) are unit-smoked. |
| pi has no permission system | ⏸ pikit's `safety` extension was ported, then removed 2026-09-05 (unused; recover from git history if a permission layer is ever wanted). |
| Context loss after compaction | ✅ `dcp/recall` + `continue-after-compaction`; APPEND_SYSTEM tells agents to `recall` before guessing. Automatic compaction needs no resume (pi continues an in-run compaction itself; a post-run one follows a finished run); the extension only resumes a run that a manual `/compact` aborted, with a prompt that runs recall → `memory_search` → reconcile → continue. |
| Harness rules never reach a consuming repo | ✅ **`setup-project.mjs`** (2026-09-14): pi loads task roles, `APPEND_SYSTEM.md`, and project settings only from `<repo>/.pi/` (or the user dir), never from a package — so `/setup-pi-myself` copies the roles and the rules and merges `enableSkillCommands: true` (existing keys win). Tested: provision set, verbatim rules, settings merge, idempotency, drift refresh. |

- The tracker's GitHub **write** path (label creation, native sub-issue and dependency edges, `claim`/`close`) is covered only by fake-runner tests; exercising it live needs a throwaway repository and a `gh` token carrying `delete_repo`, which this machine's token lacks.
- Whether `.scratch/` state gets its own recall provenance (needs dogfooding).
- Themes (catppuccin/tokyo-night) — port on request.
- Memory has no cross-project tier (pi-workspace-memory is per project slug); `state.preferences` per project is the stand-in. Revisit if personal preferences keep getting re-recorded.
- Web-research package choice (decided 2026-08-29): name-agnostic by design — this repo's host runs `pi-web-access` (`web_search`/`get_search_content`/`fetch_content`, incl. `source_check` for citations); `pi-search` (`websearch`/`codesearch`/`web_fetch`/`context7`/`deepwiki`) is the README's optional alternative. Both covered in APPEND_SYSTEM + scout; never install both alongside each other.
- `pi-review-loop`, `pi-pretty`, `pi-diff` — third-party QoL, not wired by default.
- `recall` streams and honours `AbortSignal` now, but its cache budget counts *source* bytes, not retained memory (parsed line objects cost a multiple of their text), and its LRU eviction order has no direct test because no observable result differs from the old clear-all — only performance does. A session file above `LINE_READ_MAX_BYTES` (40 MB) is still skipped and reported rather than partially read.
- GitHub body edits are read-modify-write with no optimistic concurrency: two wayfinder sessions resolving two children of one map can each read the map and write it back, losing the first gist (the local backend takes a lock for exactly this). GitHub supports conditional requests, so `If-Match` with the issue's ETag is the fix; until then, serialise map edits in one session. The same applies to `gh-block`, `gh-note`, `gh-edit` and `gh-tick` on one issue.
- `gh-frontier` and `gh-triage` list every issue with its body; at ~6.5 KB per REST object a repository around 40,000 issues exceeds the 256 MiB buffer and the op fails with a message saying to filter server-side. A GraphQL query selecting only the needed fields (or `gh issue list --search`) is the fix if a repo that size ever needs it.
- `gh-comment` does not verify its target is an issue: checking would add an API read to every comment. `gh-claim`/`gh-tick`/`gh-block`/`gh-status`/`gh-edit`/`gh-resolve`/`gh-out-of-scope`/`gh-note` all refuse a PR.
- `gh-triage` reads comments for at most 40 `needs-info` issues per call and names the ones it did not check.
- `skill-tool` mirrors pi's loader except for per-directory ignore files (`.gitignore`, `.ignore`, `.fdignore`), which pi applies while walking skill roots. Not taken because the registered roots carry no ignore files and the `ignore` dependency is not otherwise needed; add it if a consuming repo starts ignoring skills that way.
